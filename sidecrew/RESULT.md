## 判定與停點
協調者規定最多修兩輪。第二輪的冷讀者**說得出誰在做什麼、誰喜歡誰，大部分圖示也看得懂**，這是這條線第一次做到。但仍有 4 個具體沒通過的點，**我判定「部分通過」，照規定停下回報**：
1. 單顆愛心（暗戀）跟雙愛心（約會）分不出來。
2. 長椅太小，說明裡的「長椅」在畫面上找不到。
3. 「扛柴去地窖」出現在剛砍完、還站在樹旁那一刻，看起來跟畫面矛盾。其實是剛拿起柴，但柴的圖示太小。
4. 「地面 N 人」把爬梯子途中的人算在出發那一層，跟畫面對不上。
另外，冷讀者指出更根本的一點：**感情是靠字讀出來的，不是看動作看出來的**。這是這個原型的表現方式本身的問題，不是再調介面能解的。

## 冷讀抓出的原因（我自己的診斷，還沒修）
1. **說明字停在第一次出現的位置**，沒有跟著人移動，也沒有尾巴連到人頭。人走開之後就變成孤兒，還會跟小卡的即時狀態矛盾（「去砍柴」留著，人已經在扛柴）。
2. **名字互相重疊**時沒有錯開。
3. 心碎圖示本身不像心碎；靜音鍵不像喇叭。
4. 「飢餓」數字越大越餓，但條是綠色，直覺讀成「飽」。應該改成「飽足」，或把顏色跟方向反過來。
5. 爬梯子的姿勢跟一般站立一樣，看起來像卡在地板裡。
6. 直式鏡頭太近，一次只看得到 1～2 人。

## 改了什麼

## 順手修掉的兩個真 bug（都是 v3 就有，v4 人要爬樓梯才被放大）
1. **漏水沒人修時，全員精力卡 0**：v3 的吵醒判定是「三張床任何一張」，漏水期間每個躺下的人立刻被吵醒 → 強制睡 → 又被吵醒。v3 備份跑種子 2 的 900 秒，**85% 的樣本精力是 0**。
   改成只有漏水正下方那張床會被滴醒，且找床會避開漏水床。修後三個種子精力 0 的比例 0／0／0.01。
2. **搶不到東西會乾站**：自主挑的事被別人鎖住（同一棵樹、同一個暗戀對象）時，要等下一輪 1.3–2.4 秒再挑，連續失敗就站 5–12 秒。改成失敗 0.15–0.35 秒內重挑。

## 一個真的 bug：屋頂漏水會讓「正在走去睡覺」的任務被每一 tick 重建，睡眠永久卡死

跑 900 秒後發現：一旦漏水持續存在（v3 因為自主修繕權重偏低，漏水常常拖很久），
**所有人的精力永遠是 0、飢餓永遠是 100**——`updateWeather` 判斷「床上的人被吵醒」時沒檢查
任務階段，連「還在走去床邊、根本還沒躺下」的睡覺任務都一起取消；取消後強制睡眠的
`forced` 立刻被清空又立刻重新觸發，變成每 tick 重建又取消的無窮迴圈，睡眠永遠進不到
真正回血的階段。**這是 v2 就存在的邏輯，v3 因為人口變多（6 人搶 3 張床）+ 漏水更常發生才被
放大到看得出來。** 修法：只有「已經真的躺下（`phase==='work1'`）」的睡眠才會被漏水吵醒；
同時把找床邏輯從「人口對床位取模」改成「先找一張沒人用的床，真的都滿了才退回模數」，
避免人多床少時系統性撞同一張床。修完跑 2000 秒無此現象。
