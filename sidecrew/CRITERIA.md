# sidecrew v2 驗收判準（2026-09-17 重做，以下保留原文存查）

## 重做的原因（製作人原話）

「我是有點看不懂他們在幹嘛，為什麼要挖地底」——v1 拿礦換數字，活動沒有看得到的理由。
v1 完整記錄（CRITERIA/RESULT/game.js）備份於 scratchpad `sidecrew.v1bak/`，本檔只驗 v2。

**核心規則：畫面上每一個動作都要看到前因和後果，不看字就懂。**

v2 拿掉地下，改成地面橫向小聚落：森林（砍柴）→柴堆→廚房（爐子＋食物堆）→床（屋頂會漏水）→
田（會成熟的作物）→兩塊空地（柴夠了會出現藍圖，蓋好會有新人從畫面邊走進來）。
所有資源都是畫面上的實體堆（柴堆／食物堆疊高變矮），小人搬東西時手上看得到那樣東西。

三條循環：
1. 肚子餓（頭上飯碗）→ 去廚房吃 → 食物堆變矮；食物堆補充靠：田熟了 → 收成 → 抱著作物走回廚房 → 食物堆變高。
2. 下雨 → 屋頂滴水 → 正在睡覺的人被吵醒（不開心圖示）→ 有人扛柴去修 → 柴堆變矮；柴堆補充靠：去砍樹 → 扛木頭回柴堆 → 柴堆變高。
3. 柴堆夠多（≥4）→ 空地上出現虛線藍圖 → 蓋房子（消耗柴堆）→ 房子蓋好 → 一個新小人從畫面邊走進來、變成聚落一員。

玩家操作不變：點人→點地方（點樹＝砍柴、點成熟的田＝收成、點漏水處＝修屋頂、點藍圖空地＝蓋房子）。
自主 AI 的候選權重刻意讓「大家搶著砍柴、沒人收成」這種偏頗會發生，玩家插隊指派收成/修繕/建造
時，看得出明顯改善。

## 判準①：被指派的人一定先做指派 —— 同 v1

`task.assigned===true` 時不可能被自主換成 eat/sleep/chat/wander，唯一例外是飢餓瀕死
（hunger≥95，且此時 foodPile 要有存量才能真的去吃，否則維持原任務——留意這是 v2 新增的
邊界：沒東西吃就不會半路跑去吃空氣）。中斷要有明顯圖示。

## 判準②：做完一定回日常、不發呆 —— 同 v1，門檻不變（3 秒內）

第一次量到 3.3 秒，超過門檻——原因是自主決策計時器 `decideAt` 在任務完成時可能還剩一大段
沒歸零。修法：`endTask()` 把 `decideAt` 收斂到 0.2–0.6 秒之間，不留舊的等待值。
修完重量：**0.5 秒**，通過。

## 判準③：同時指派 3 人，5 秒後看得出誰在做什麼 —— 同 v1

真滑鼠指派 3 個人做 3 種不同的事（砍柴／修屋頂／收成或蓋房子，依當下場上什麼可行決定），
5 秒後截圖：三人的位置、手上拿的東西（木頭／作物圖示）、頭上的「！」與虛線要能各自對應到
不同任務。

## 判準④（新）：冷讀——不給任何說明，讓沒背景的人看畫面猜因果

用 Agent 工具開一個全新、無背景的子代理人，只給它 3 張間隔 20 秒（真實時間，不加速）的
截圖，不给任何文字說明，請它描述「這些小人在做什麼、為什麼」，並列出看得出的因果鏈。

**判準**：它列出的因果鏈裡，至少 3 條要對應到遊戲裡真的存在的機制（例如「下雨→漏水」
「柴堆變少→有人在搬柴」「新房子出現、人數變多」），允許用詞不精確，但因果方向要對。
少於 3 條算不通過，要回頭檢討是哪個環節的視覺線索不夠（先看是「有沒有畫出來」還是
「畫出來了但不夠顯眼」）。

## 判準④ v3 版：冷讀要多認出至少 1 條「人跟人」的事

同樣全新、無背景的子代理人，只給 3 張間隔 30 秒（真實時間，不加速）的截圖，不给文字說明。

**判準**：因果鏈至少 3 條對應到真機制，其中**至少 1 條**要是人跟人之間的事（例如「誰喜歡誰」
「誰看起來難過／頭上有心碎圖示」「兩人湊在一起」），其餘可以是原本的下雨/蓋房/資源鏈。
少於 3 條、或 3 條裡完全沒有感情線，都算不通過。
