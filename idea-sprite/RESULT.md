# 拾取點子精靈 — 測試結果

測試方式：Playwright headless（844×390），`window.__idea` 測試掛鉤驅動流程，並額外用真的鍵盤／滑鼠指標事件（模擬手機按鈕）跑過一次核心機制，不全靠掛鉤。全程 `page.on('pageerror'/'console error')` 監聽，**全程 0 個錯誤**。

## 對照 CRITERIA.md 逐條檢查

- **有沒有落差（演示小關 vs 主世界）**：三個演示小關的天空色各自跟主世界（深藍海軍色）完全不同——跳躍示範是暖橘色、生命值示範是暗紅色、三選一示範是紫色星空——而且都是單畫面、無鏡頭捲動、裝飾降到最低，跟主世界「有背景層、有鏡頭跟隨、有一堆物件」的密度明顯不同。回主世界那一刻背景層數立即增加（見下）。**過**。
- **看不看得懂剛撿到什麼**：三個點子分別對應完全不同顏色的粒子／飛行圖示（黃=跳躍、紅=生命、藍=三選一），落地位置也不同（跳躍鍵在右下角彈出、愛心在左上角長出、三選一只在右上角小圖示欄多一格），不用讀標題文字也能靠「畫面上多了什麼、長在哪裡」分辨。標題文字（跳躍／生命值／三選一）只當輔助，1.6 秒淡入淡出。**過，但這條最弱**——三個顏色/位置線索差異明顯，可是沒有找完全不懂遊戲語彙的人驗證過，只能說「有給非文字線索」，不能保證真的所有人都看得懂。
- **UI 是不是憑空出現**：實作了飛行圖示動畫（點子球位置→目標 UI 位置，拋物線＋落地彈跳縮放），愛心／跳躍鍵／三選一圖示欄格子都是這樣「長」出來的，不是瞬間切換。**過**。
- **世界有沒有變豐富**：`ideas.jump/health/choice` 三個旗標各自控制一層背景（遠山剪影／雲層／星空+遠山），視覺上一格一格疊上去，實測畫面確認三層都有疊加（見截圖 `hearts_check.png`：同時看到山丘剪影＋雲層）。**過**。
- **三選一是不是裝飾**：`choosePopup` 會實際修改 `pl.speed` / `pl.maxHearts+hearts` / `pl.jumpVel`，用掛鉤選「跳更高」後 `state().jumpVel` 從 -190 變成 -231.8，數值確實變了。**過**。
- **打擊感**：跳躍、落地、拾取、受傷、開門、選擇都各自綁了程式合成音效＋粒子爆發；受傷/墜坑/踩釘刺都有畫面震動（`shake`）。headless 環境沒有使用者手勢，WebAudio 實際發不出聲音是測試環境限制，不是程式邏輯缺陷（`audio()` 掛在 keydown/pointerdown 上，真人操作會觸發）。**過（結構上成立，未實機聽過聲音）**。
- **卡關**：用真鍵盤／真滑鼠分別玩過一輪——鍵盤走位＋跳躍闖過跳躍示範關（3 次真跳躍過縫隙，非掛鉤）、真的跳過主世界的坑、真的用滑鼠按住右鍵按鈕移動角色。跳躍間隔（縫隙 20px／坑 42px）跟角色跳躍距離（約 61px）都有實測留足餘裕。**過**。
- **文字依賴**：拿掉標題文字後仍靠顏色/位置/動畫辨識三個點子（見上）；三選一彈窗本身有短標籤（4 字內），這是判準允許的「最多一行短標題」等級，不是敘事文字。**過**。

## 三個點子落差是否互不相同

- 跳躍：示範是平台跳關卡，回來後多一顆「按鈕」＋世界多一段跨不過的坑。
- 生命值：示範是被釘刺打、被迫死一次重來，回來後多一排「血條」＋世界多會扣血的釘刺。
- 三選一：示範是開寶箱的小動畫（無太大殺傷力/低風險），回來後多一個「數值選擇」，而且選完真的改變手感。
三者一個是「新能力」、一個是「新資源/風險」、一個是「新決策點」，形狀不同，不是同一招換皮。**過**。

## 過程中抓到並修掉的問題（不是最終狀態的美化，如實記錄）

1. **點子撿不到**：原本用 `Math.hypot` 同時比較 x/y 距離，但 orb 的 y 座標本身跟角色重心差 17px，導致半徑 16 永遠碰不到——三個點子在自動測試裡一次都沒觸發過。改成只比較水平距離（`Math.abs(pl.x - ORB_X) < 14`）修好。
2. **角色一開場疊在左移動按鈕上面**：開場站位 x=30 跟左鍵按鈕範圍重疊，畫面上角色卡在按鈕框裡。把開場 x 移到 110。
3. **跳躍示範關的跳躍鍵蓋住終點旗**：兩個 UI 都釘在螢幕右下角同一塊。跳躍示範改用獨立的 `jumpBtnDemo`（移到右上角），跟終點旗分開。
4. **愛心圖示用 0.7 縮放＋ctx.scale 疊加，字體級的小圖示會糊成看不清楚**：改回整數縮放（1.0），確認穩定狀態下三顆心清楚可辨（見 `hearts_check.png`）；一開始截圖抓到的是「正在淡入」的過渡幀，不是永久缺陷。
5. **結尾畫面角色疊在「重來」按鈕下面**：兩者 y 座標都落在同一段，角色被按鈕蓋住。把角色 y 從 groundY 移到 118，跟按鈕（y150起）分開。

以上都是實測跑出來才發現、不是憑空猜的；改完都重新截圖／重新跑過整輪流程確認。

## 沒有驗證到的部分（誠實列出）

- 沒有真人手指觸控測試，只能驗證滑鼠/pointer 事件邏輯路徑，跟真實手機觸控行為理論上一致但沒有實機跑過。
- 沒有實際聽到音效（headless 無使用者手勢，WebAudio 不會真的出聲），只驗證了呼叫路徑存在。

## 2026-09-17 改版：拿掉三選一，換成存檔點

製作人回饋：「三選一不適合這遊戲，這遊戲沒有需要三選一的理由」。改動：

  學會生命值之後、學會存檔點之前，插入一段刻意設計的「痛段」（`GAUNTLET_START=420` 到

  第三個點子「存檔點」的示範關：走過一支旗子（亮起、有音效/粒子）→ 故意走進尖刺死一次→
  從旗子重生，不是從關卡開頭——全程沒有一個字說明，只靠畫面（死亡動畫→重生位置）表達。
  回主世界吸收後，之前走過的路（110/420/700/1220）長出旗子，之後死亡一律從「最近的、

### 實測（真輸入驅動，非全靠 skip 掛鉤；對照 CRITERIA.md 新增的四條）

1. **痛段真的會痛**：學會生命值後，站到 `x=420`（痛段起點）用真鍵盤持續按右鍵、完全不跳，
