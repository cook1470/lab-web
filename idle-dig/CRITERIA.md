# 驗收標準（寫死，動手前定）

只驗一件事：

> **回來看的時候礦坑明顯變大了、而且有一個值得點的決定在等我。**

## 「明顯變大」怎麼量

用 `window.__idle.skip(seconds)` 在同一頁面連續推進模擬時間，
在 skip(0)／skip(10)／skip(3600)／skip(28800) 四個時間點各截一張圖，四張圖要能一眼看出差異：

- 畫面上的「深度」數字要不同（不是四捨五入後看起來一樣）
- 礦坑剖面的地層顏色/裝飾要隨深度換代（淺層土色 → 深層岩石 → 更深的水晶/遠古層），
  不能四張圖背景色都一樣
- 礦工圖示數量或動畫不能四張長得一模一樣（若玩家全程沒手動雇工，至少深度/金幣/地層要變）

**沒過的判定**：
- 四張截圖用肉眼比對，看不出差異 → 沒過
- 或者：回來時找不到任何一個「可以點、值得點」的東西
  （所有升級都已經買到滿、金幣多到沒有下一步可花）→ 沒過

## 設計保證（避免「全部點滿」）

雇礦工／升級鑽頭／升級升降梯／升級背包 四項全部是**無上限等級**，
每買一次下一級成本才會往上長；沒買的項目成本停在原地。
金幣速率跟深度（會一直自動變深）掛鉤、深度不看玩家買不買東西照樣漲，
所以就算完全不點，金幣也會漲到「原本很便宜的雇工成本」變得輕鬆負擔得起——
**沒有「全部升滿」這個終點狀態**，永遠有下一步可點。

## 離線收益驗法

1. 用 skip() 或直接改 localStorage 存的 `lastTs` 往前推一段時間，重新整理頁面
2. 應該出現一張小卡片（不是全螢幕彈窗）：「你不在時：+金額、+深度」
3. 點一下收下，數值才真正加進本體状態，卡片消失
4. 不點也不會壞——只是那筆離線收益暫時沒進帳，下次開也還在

## 其他檢查

- 開頁面 console 全程無 JS error
- 預設靜音（喇叭圖示在角落、可點開關）
- 沒有畫面閃爍、沒有大彈窗
- 手機寬度（可用 iPhone viewport 檢查）版面不破版
